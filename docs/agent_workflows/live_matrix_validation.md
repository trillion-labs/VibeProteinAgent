# Live Matrix Validation Runbook

Use this runbook when validating VPA agent workflows across Codex, Claude Code,
and OpenRouter/Qwen-style providers. It is operational guidance only; do not
change runtime behavior from this document.

## Preflight

Run from the VPA repo root on the validation node:

```bash
source /mnt/vast/trillion/hyunjin/.vibeproteinagent/env.sh
which codex && which claude
bash /mnt/vast/trillion/hyunjin/auth/setup_links.sh

PYTHONPATH=/mnt/vast/trillion/hyunjin/VibeProteinAgent/src \
/mnt/vast/trillion/env/miniconda3/envs/vpa/bin/python -m vibeproteinagent.cli.main \
  install run --tools boltzgen --yes --repair

export OPENROUTER_API_KEY="..."
export VPA_OPENROUTER_CREDENTIAL="${OPENROUTER_API_KEY}"
export HF_TOKEN="..."
export VPA_HF_CREDENTIAL="${HF_TOKEN}"
```

For PXDesign-related validation, ensure `VPA_PXDESIGN_PIPELINE_ENV` points to
the environment expected by the PXDesign pipeline on the node. Treat missing
provider login, missing token, missing tool install, or unavailable GPU memory
as environment failures unless deterministic tests reproduce a code defect.

## Running The Matrix

```bash
STAMP=$(date +%Y%m%d_%H%M%S)
RUN_DIR=validation_runs/full_canonical_matrix_v3_${STAMP}
RUNNER_LOG="${RUN_DIR}.runner.log"

bash validation_runs/run_live_provider_matrix_vm024.sh \
  --providers codex,claude,qwen \
  --output-dir "${RUN_DIR}" \
  2>&1 | tee "${RUNNER_LOG}"
```

If rerunning only known failed cases, keep `plan_only=0` for actual execution
cases and record which prior successful cases are being reused as PASS evidence.

## Phase Tracking

Classify each case by the deepest phase reached:

- provider preflight;
- planning and provider response parsing;
- compiler/fixup and parameter ownership validation;
- workflow node execution;
- merge/rank/decision;
- submit candidate or answer;
- report generation.

Do not diagnose only from final artifacts. Inspect runner logs, case logs,
workflow status, node/job status, and generated reports. When a case fails,
record the first failing phase, tool/node/job id, normalized error code, and the
contract that was violated.

## PASS Evidence

For each successful case, collect:

- provider and model;
- workflow family and case name;
- run directory/workspace;
- workflow id and final decision;
- submitted candidate or answer summary;
- report path generated by `vpa report`;
- notes for environment caveats or rerun provenance.

For a PASS-only report set, create a new validation folder with one manifest and
one report per successful case. Keep the source run directory for each report in
the manifest so reruns and reused prior PASS cases remain auditable.

## Failure Classification

Code failure examples:

- compiler lets planner-owned candidate payloads reach executor validation;
- downstream source artifacts are incorrectly accepted as planner literals;
- prior-round candidates are read from summaries instead of archive snapshots;
- submit uses a node alias that is not resolved to a real `job_...` id.

Environment failure examples:

- provider CLI is not logged in for the non-interactive shell;
- OpenRouter/HF credentials are absent or expired;
- required conda/tool environment is missing;
- GPU memory is exhausted by unrelated jobs.

When in doubt, reproduce with a deterministic unit or direct workflow harness
before editing runtime code.
